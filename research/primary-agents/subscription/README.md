## What this protects

A process started independently inside the workspace can access only that container's processes, filesystem and assigned services. Factory starts the trusted controller separately. Workspace code gets neither the account files nor an endpoint that exports them. File contents and tool results returned to the controller remain untrusted. The controller must use a private working directory and managed configuration, exclude project-provided executable hooks or plugins, and route every enabled operation that touches the project into the workspace. A writable shared home or unrestricted controller command tool would invalidate this design.

The experiment used CLI processes on the host and an empty controller directory. Only the test harness had permission to start the disposable Podman worker. The marker tool ran in that worker. For a supported feature, supervise the CLI in a dedicated trusted environment and attach the user's terminal to it. Keep the container-engine socket out of both the user workspace and the CLI’s tool set. The operator can still use the normal subscription and quota interface. Codex’s quota API was exercised. Claude and Google quota panels were not exercised in this follow-up. Workspace tasks can consume the signed-in account’s allowance, even though they cannot directly read its credentials from a nonexistent mount.

## Existing alternative

Docker Sandboxes documents host-managed OAuth for both Codex and Claude Code. The host stores the real account credential, and the sandbox receives a placeholder. This is an existing answer for users willing to run that sandbox runtime. It is a separate microVM system with its own networking, account and lifecycle. Its documentation lists Ubuntu for Linux local sandboxes. This host uses Fedora and has KVM, but the Docker Sandboxes CLI is not installed. The live tests above used Factory’s existing Podman environment. Docker lists no equivalent built-in Antigravity integration on its credentials page. Do not extrapolate Docker’s supported Claude flow into permission for Factory to collect or relay user tokens. [Docker credentials](https://docs.docker.com/ai/sandboxes/configuration/credentials) · [Docker installation](https://docs.docker.com/ai/sandboxes/install/) · [Anthropic authentication terms](https://code.claude.com/docs/en/legal-and-compliance)

## Repeat the positive tests

From the repository root, use a Linux host with Podman, `socat`, locally signed-in native CLIs, and a locally available Factory dev image. Set `DEV_IMAGE` to the image name and `CODEX_BIN` to the absolute path to the native executable. Run `sh research/primary-agents/subscription/run.sh`. This sends short live prompts to the three account sessions. The helper creates and removes a private directory and an offline worker. Codex retains its native editing tool. The Claude and Google fixtures deliberately expose one fixed remote read and do not implement a general coding adapter.
